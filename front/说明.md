# 第 2 步：前端

> 起一个 nginx 容器，对外提供 **80 端口**：静态页面 + 把 `/api` 反代到第 3 步的后端。
> 不需要构建镜像——直接用官方 `nginx:1.27-alpine`，页面和配置靠挂载。

**顺序说明**：前端可以先起，但这时候它反代不到后端（第 3 步还没起），打开页面也行、调接口会 502。**这是正常的**，起完第 3 步就好了，不用回头重启前端。

---

## 本步要放的文件

放到服务器 **`/opt/smartp/frontend/`**：

```
/opt/smartp/frontend/
├── docker-compose.yml     ← 本目录的文件
├── nginx.conf             ← 本目录的文件
└── static/
    ├── index.html
    ├── app.js
    └── styles.css
```

> 本目录里**没有** Dockerfile —— 前端不构建镜像。原来那个 `frontend/Dockerfile` 是备用方案（想把前端烤进镜像时用的），这次不用，已经删掉了，免得混淆。

## 执行

```bash
# 前置检查：第 1 步建的网络还在不在
docker network ls | grep smartp-net
# 没有的话补建：docker network create smartp-net

cd /opt/smartp/frontend
docker compose up -d
```

### 🔴 上传完之后一定要改权限 —— 否则访问 IP 报 403

这是实测踩到的坑。上传上来的目录如果是 `drwx------`（700），浏览器打开就是 **403**，nginx 日志里是：

```
"/usr/share/nginx/html/index.html" is forbidden (13: Permission denied)
```

原因：nginx 镜像里 **master 进程是 root，但干活的 worker 进程是 `nginx` 用户**（`ps` 实测：`nginx 22 nginx: worker process`）。目录是 700 的话，worker 连目录都进不去，里面的文件全部"禁止访问"。

**每次上传完都执行一遍**：

```bash
chmod 755 /opt/smartp/frontend
chmod -R a+rX /opt/smartp/frontend
```

> `a+rX` 里大写的 `X` 是"只给目录加执行位"——目录必须有 `x` 才能被穿过，普通文件不需要。所以用 `-R a+rX`，不要用 `-R a+rx`。

**改完立刻生效，不用重启容器**——`static/` 是 bind mount，容器里看到的权限就是宿主机上的权限。

### 🔴 别删 `/opt/smartp/frontend/` 目录本身

如果宿主机上的挂载源目录被删了，**运行中的容器看起来还正常**——因为挂载点在容器启动时就绑定了 inode，源目录删掉后内核还替它留着（"幽灵挂载"）。但**容器一重启就全空了**。

所以收尾时用 `ls /opt/smartp/frontend/static/` 确认目录还在。

## 验收

```bash
docker ps --format '{{.Names}}|{{.Status}}' | grep frontend
# 期望：smartp-frontend|Up ...     （不是 Restarting）

# 页面能打开（第 3 步没起时，这个也应该返回 200，因为是纯静态）
curl -s -o /dev/null -w 'page=%{http_code}\n' http://172.26.55.198/

# 看 nginx 报错
docker logs --tail 20 smartp-frontend
```

### 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器一直 `Restarting (1)` | nginx 启动时解析不到 `smartp-backend` | 说明第 3 步的后端还没起，或者没在同一个网络。**nginx 只在启动那一刻解析 upstream**，所以第 3 步起完后要 `docker restart smartp-frontend` |
| 打开是 502 Bad Gateway | 后端没起 / 不在同一网络 | `docker exec smartp-frontend getent hosts smartp-backend` 看看能不能解析到 IP |
| 页面 404 / 样式丢了 | 挂载路径不对 | `static/` 里的三个文件必须直接在这一层，不是 `static/static/` |

### 关于 502 和 nginx 的一个坑

`nginx.conf` 里是这么写的：

```nginx
upstream smartp_backend {
    server smartp-backend:9900;
}
```

nginx **只在启动时解析一次** upstream 的域名。所以：

- **顺序无所谓**，但**第 3 步后端起来之后，要 `docker restart smartp-frontend`**，让它重新解析一次
- 以后后端容器重建（IP 变了），前端也要跟着重启一次

## 改页面 / 改配置怎么生效

因为是挂载的，不用重建：

```bash
# 改了 static/ 里的页面 —— 直接刷新浏览器就行（nginx.conf 里已经关掉了静态资源缓存）

# 改了 nginx.conf —— 要 reload
docker exec smartp-frontend nginx -t                  # 先测语法
docker exec smartp-frontend nginx -s reload           # 再热加载
```
