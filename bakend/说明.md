# 第 3 步：后端

> FastAPI 主应用 + 两个 MCP 服务打包成**一个容器**，只暴露给同网络的 nginx。
> 这是三步里唯一需要**构建镜像**的一步。

---

## 本步要放的文件

放到服务器 **`/opt/smartp/backend/`**：

```
/opt/smartp/backend/
├── docker-compose.yml     ← 本目录的文件
├── Dockerfile             ← 已包含 static 占位目录 + MCP 启动命令
├── .dockerignore
├── .env                   ← 🔴 已改好，见下面「改了哪 4 项」
├── pyproject.toml         ← 🔴 依赖已锁版本，见下面「为什么锁」
├── README.md
├── Makefile               ← 含 make upload 灌库命令
├── app/                   ← 业务代码
├── mcp_servers/           ← cls_server.py / monitor_server.py
├── aiops-docs/            ← AIOps 知识库文档
├── uploads/               ← 待灌入的文档
├── static/                ← 【必须是空目录】不能删！见下
└── logs/                  ← 空目录，容器往里写日志
```

### 🔴 `static/` 必须是「空目录」，不能删

`app/main.py` 里有 `app.mount("/static", StaticFiles(directory="static"))`。Starlette 在目录**不存在**时会在 **import 阶段**直接抛 `RuntimeError: Directory 'static' does not exist`，容器根本起不来。留个空目录就行——前端页面实际由第 2 步的 nginx 提供，这个 mount 永远访问不到。

（Dockerfile 里也 `mkdir -p /app/static` 了，双保险。）

## 这版 `.env` 改了什么

| 项 | 原值 | 新值 | 为什么 |
|---|---|---|---|
| `MILVUS_HOST` | `localhost` | `172.26.55.198` | 容器里的 `localhost` 是**容器自己**。Milvus 在另一个容器里，连不上。改成虚拟机内网 IP（它的 19530 已映射到宿主机） |
| `PROMETHEUS_BASE_URL` | `http://localhost:9190` | `http://172.26.55.198:9190` | 同上，Prometheus 也是另一个容器 |
| `APP_URL` | `http://39.107.61.117:9090` | `http://39.107.61.117` | 原来那个端口是 Prometheus 的；通知卡片按钮应该走 nginx 的 80 端口 |
| `DEBUG` | `True` | `false` | 生产环境别开 |

**没改、也不该改的**：`MCP_CLS_URL` / `MCP_MONITOR_URL` 保持 `localhost:8003` / `8004` —— 两个 MCP 服务和主应用在**同一个容器**里，同一个网络命名空间，那里的 localhost 是对的。

> 为什么不用公网 IP `39.107.61.117`？实测容器访问自己的公网 IP 会超时（errno=11）——需要 NAT 回流（hairpin NAT），阿里云默认不支持。

## 为什么 `pyproject.toml` 锁了三个版本

```toml
"langchain-mcp-adapters>=0.2.1,<0.3.0",
"fastmcp>=2.14.0,<3.0.0",
"mcp>=1.26.0,<2.0.0",
```

上一轮部署就是崩在这里：

```
ImportError: cannot import name 'RequestContext' from 'mcp.shared.context'
```

链条是：`langchain-mcp-adapters 0.3.1` 自己的约束只写了 `mcp>=1.24.0`（**没有上限**），而 `fastmcp 4.x` 会把 `mcp` 拖到 2.x。**`mcp 2.x` 把 `mcp.shared.context.RequestContext` 改名成了 `BaseContext`**，adapters 还按老路径导入 → 容器一启动就 ImportError。

（上游到 `adapters 0.3.2` 才补上 `mcp<2.0.0`，这个镜像正好卡在窗口期。）

**别把这三行删掉或者放开上限**，否则下次重建还会中招。

## 执行

```bash
# 前置检查：网络在不在
docker network ls | grep smartp-net
# 没有就补建：docker network create smartp-net

cd /opt/smartp/backend

# 构建镜像（pyproject.toml 变了会让依赖层重新装，大概几分钟）
docker compose build

# 起容器
docker compose up -d
```

### 🔴 改了 `.env` 之后必须 `--force-recreate`，不能只 `restart`

compose 的 `env_file` 是**建容器时**把变量注入进去的，而 pydantic-settings 里**环境变量的优先级高于 `.env` 文件**。所以只 `docker restart` 的话，容器会继续用旧的 `localhost`。

```bash
docker compose up -d --force-recreate backend     # 正确
```

## 验收

```bash
# 1) 容器在跑（不是 Restarting）
docker ps --format '{{.Names}}|{{.Status}}' | grep backend

# 2) 依赖版本对（关键！）
docker exec smartp-backend pip list | grep -E '^(mcp|fastmcp|langchain-mcp-adapters) '
#   期望：mcp 1.30.0 / fastmcp 2.14.7 / langchain-mcp-adapters 0.2.2
#   如果 mcp 是 2.x —— 说明 pyproject 的锁定没生效，回去检查

# 3) 启动日志：应该看到 Milvus 连接成功 + Uvicorn running
docker logs --tail 40 smartp-backend

# 4) 两个 MCP 服务起来了（在容器内部，有 8003 / 8004 在听）
docker exec smartp-backend sh -c "python -c \"
import socket
for p in (8003, 8004, 9900):
    s=socket.socket(); s.settimeout(2)
    print(p, 'OK' if s.connect_ex(('127.0.0.1',p))==0 else 'FAIL'); s.close()
\""

# 5) 整条链路（这一条要第 2 步的前端也起着）
curl -s -o /dev/null -w 'health=%{http_code}\n' http://172.26.55.198/health
curl -s -o /dev/null -w 'page=%{http_code}\n'   http://172.26.55.198/
```

**第 5 条 `health` 返回 200 才算成**（Milvus 不通时它返回 503）。

第 3 步起完后，**回头重启一下前端**，让 nginx 重新解析一次后端地址：

```bash
docker restart smartp-frontend
```

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 起来就 `ImportError: cannot import name 'RequestContext'` | pyproject 的版本锁被放开了 | 确认 pyproject 里那三行还在，然后 `docker compose build` 重建 |
| 起来就 `Milvus 操作失败: illegal connection params or server unavailable` | Milvus 没起 / `.env` 里还是 localhost | 先看 `docker ps \| grep milvus`；再看 `.env` 的 `MILVUS_HOST` |
| 改了 `.env` 但没生效 | 只 restart 了，没有 recreate | `docker compose up -d --force-recreate backend` |
| 容器反复重启 | Milvus 连不上（lifespan 里 `milvus_manager.connect()` 没有 try/except，连不上直接崩） | 先把第 1 步的 Milvus 弄稳 |
| `RuntimeError: Directory 'static' does not exist` | `static/` 空目录被删了 | `mkdir -p /opt/smartp/backend/static` |
| 容器起来了但只有本地工具、少 7 个 MCP 工具 | MCP 服务没起来 | 看 `docker logs smartp-backend` 开头，正常应该能看到两个 MCP 的启动输出 |

## 一个已知问题（本轮没改）

`app/main.py` 的 lifespan 里 `milvus_manager.connect()` **没有 try/except** —— Milvus 不通时应用会直接崩溃，然后被 `restart: unless-stopped` 拉起来再崩，形成重启循环。`/health` 在 Milvus 不通时也返回 503。

这是照你之前"不改容错代码"的要求保留的。**所以 Milvus 必须先稳**，不然后端会一直重启。
