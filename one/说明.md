# 第 1 步：基础设施

> 起 7 个容器：Postgres、Redis、Neo4j、Milvus（etcd + MinIO + 本体）、Prometheus、Node Exporter、Alertmanager。
> 这一步**只碰基础设施**，不碰 SmartP 的前端后端。

---

## 🔴 先做一件事：加 swap

这台机器只有 **1.7GB 内存、没有 swap**，上次 Milvus 就是这么死的——内存吃紧导致 etcd 延迟抖动（日志里 `apply request took too long` 到了 888ms），Milvus 的会话保活超时，自己退出了。

```bash
free -m                                     # 先看，Swap 那行应该是 0

fallocate -l 4G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
sysctl -w vm.swappiness=10

free -m                                     # 再看，Swap 应该有 4096 左右
```

磁盘剩 25G，够用。**不加这步，后面全白干。**

## 本步要放的文件

全部放到服务器 **`/root/`** 目录下：

```
/root/
├── docker-compose.yml     ← 本目录的文件
├── prometheus.yml         ← 本目录的文件
├── alertmanager.yml       ← 本目录的文件
├── alert_rules.yml        ← 本目录的文件（注意！服务器上现在是个目录，见下）
│
├── pgdata/                ← 已有数据，不动
├── redisdata/             ← 已有数据，不动
├── neo4jdata/             ← 已有数据，不动
├── milvusdata/            ← 🔴 已有数据（Milvus 的 collection 都在这里），不动
├── prometheus_data/       ← 已有数据，不动
└── alertmanager_data/     ← 已有数据，不动
```

### 🔴 为什么必须放在 `/root/`

compose 里所有 volume 都是 `./pgdata`、`./milvusdata` 这种**相对路径**，相对于 compose 文件所在目录。你现有的数据全在 `/root/` 下——**文件放错地方 = Milvus 变成空库**。

### 🔴 `alert_rules.yml` 现在是个「目录」，不是文件

服务器上 `ls -ld /root/alert_rules.yml` 显示的是 `drwxr-xr-x`（目录）。docker-compose 把它挂进容器后，Prometheus 读不到告警规则。

上服务器后先确认它是空的，再删掉换成文件：

```bash
ls -la /root/alert_rules.yml       # 确认里面没有你要的东西
rm -rf /root/alert_rules.yml       # 确认是空目录后再删
```

## 执行

```bash
# 1) 先建共享网络（第 2、3 步都要用，只建一次）
docker network create smartp-net

# 2) 修 Prometheus 数据目录的属主
#    官方镜像里 Prometheus 以 nobody(65534) 身份运行，而 /root/prometheus_data
#    如果是 root 所有，它写不了 queries.active，会直接 panic 退出
#    （错误：open /prometheus/queries.active: permission denied）
mkdir -p /root/prometheus_data
chown -R 65534:65534 /root/prometheus_data

# 3) 起基础设施
cd /root
docker compose up -d
```

## 验收

```bash
# 7 个容器都应该是 Up
docker ps --format '{{.Names}}|{{.Status}}'

# Milvus 健康检查（它对外暴露 9091 健康口）
curl -s http://172.26.55.198:9091/healthz && echo "  <- Milvus OK"

# Prometheus 应该能打开
curl -s -o /dev/null -w 'prometheus=%{http_code}\n' http://172.26.55.198:9190/-/healthy

# 端口都在听
ss -lnt | grep -E '19530|9091|9190|9093|9100|5432|6379|7687'
```

**Milvus 要等 1~2 分钟才 ready**，刚起完 `docker logs milvus_db` 里还有报错是正常的。等不动了再看：

```bash
docker logs --tail 30 milvus_db
```

### 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `network smartp-net declared as external, but could not be found` | 忘了建网络 | 执行上面的 `docker network create smartp-net` |
| prometheus 一起来就退出，日志有 `queries.active: permission denied` | 数据目录属主不对 | 执行上面的 `chown -R 65534:65534 /root/prometheus_data` |
| milvus_db 起来了又退出，日志有 `disconnected from etcd and exited` | 内存不够，etcd 抖动 | 回去看 swap 加了没；还不行就得做减法（比如不用 Neo4j 就把它注释掉，省 ~350MB） |
| prometheus 报 `alert_rules.yml: is a directory` | 就是上面那个目录问题 | 删掉目录，换成文件 |

## 内存账（重要）

这台机器 1.7GB 内存要跑 7 个基础设施容器 + 后面 2 个 SmartP 容器，**很紧**。当前实测占用：

```
neo4j_db        348 MB    ← SmartP 用不到它，不需要就注释掉
milvus_minio     96 MB
postgres_db      19 MB
milvus_etcd      16 MB
alertmanager     13 MB
redis_db          4 MB
node_exporter     3 MB
（Milvus 本体和 Prometheus 起来后还要各加几百 MB）
```

如果 Milvus 还是反复死，第一个该砍的就是 **Neo4j**（compose 里那段整段注释掉，再 `docker compose up -d --remove-orphans`）。
